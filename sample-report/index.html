Risk Considerations

This tool is read-only: it never modifies, deletes, or disables anything in Splunk. It only reads metadata (ingest volume and usage signals) — see docs/security.md.

These figures are estimates based on Splunk metadata (ingest volume and search/alert/dashboard activity), not a financial audit.

Datasets classified as PROTECTED were deliberately excluded from optimization candidates, regardless of their usage signals.

Datasets classified as UNKNOWN are excluded from the estimate — we could not determine their usage with high confidence, so we do not guess.

This report analyzes usage at the (index, sourcetype) level only. Splunk's license usage reporting can "squash" host and source breakdowns in high-cardinality environments — see Methodology.

No action should be taken without manual validation by a Splunk administrator and the team that owns each dataset.

Recommendations

  • Validate each optimization candidate with the team that owns the data before changing anything.
  • For confirmed low-value high-volume sources, consider filtering at the forwarder (e.g. INGEST_EVAL / props.conf transforms) rather than disabling the input entirely.
  • For data that is rarely queried but must be retained for compliance, consider a cheaper storage tier instead of reducing ingest.
  • Re-run this audit periodically (e.g. monthly) — usage patterns change as teams build new dashboards and alerts.
